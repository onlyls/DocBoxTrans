# 稳定性修复验收

## 自动检查

在 `DocBoxTrans-Zotero` 中执行：

```sh
npm ci
npm test
npm run build
```

测试使用 Node 内置测试运行器与项目已有的 esbuild，不新增测试依赖、不连接外部翻译服务、不读取用户的 Zotero 数据。覆盖历史迁移、标签保留、读写异常、保存并发、旧请求回写、空译文、取消请求、目标语言、温度为零、多阅读器状态、快捷键和关闭保存。

结构整理阶段另增加真实侧栏模块的离线交互测试，以及引擎返回约定、状态通知隔离、布局资源释放和运行时循环依赖检查。模拟 DOM 不覆盖真实浏览器排版；参见 [代码结构说明](architecture.md)。

构建产物为 `build/doc-box-trans-for-zotero.xpi`。当前保持原有包版本，尚未发布新版本。

## Zotero 内手动验收（尚待执行）

建议在单独的测试配置中安装插件，并准备两份 PDF。先备份已有的 `docboxtrans-history.jsonl`，不要通过修改正式历史文件的权限来模拟故障。

| 场景 | 操作 | 预期 |
| --- | --- | --- |
| 重译与标签 | 翻译并打标签，关闭译文复用，再翻译同一段 | 标签仍在，同版本只有一条记录 |
| 多译文版本 | 同一段切换引擎，再切换目标语言 | 各版本分别保留，原文跳转仍可用 |
| 请求乱序 | 慢接口翻译期间切换引擎，连续划选新段落 | 旧请求取消，当前显示和记录中的引擎与译文一致 |
| 空译文 | 用测试接口返回空内容，对拼合区发起翻译 | 显示失败，片段保留；成功重试只删除本次送出的片段 |
| 目标语言 | 默认和自定义系统提示词分别选择英语翻译 | 使用英语；`{targetLanguage}` 被替换；温度 `0` 可用 |
| 多文献 | 打开两篇文献，交替划选、切换服务及追加拼接 | 选区、当前译文和追加操作属于各自阅读器 |
| 多窗口 | 将同一 PDF 分别在主窗口与独立阅读器窗口打开 | 两个窗口分别保留选区和当前译文，快捷键作用于活动窗口 |
| 关闭弹窗 | 关闭“显示翻译弹窗”，执行划词和拼接翻译 | 侧栏仍显示正确状态和结果 |
| 保存恢复 | 在测试配置中制造暂时性文件读写错误，再恢复 | 侧栏显示提示，原文件保留，重试后旧记录和新记录均在 |
| 退出与重载 | 翻译后立即退出，再启动；快速禁用并启用插件 | 成功记录保留，界面和事件处理不会重复注册 |
| 兼容性 | 在项目声明支持的 Zotero 版本分别执行以上场景 | 记录具体版本与结果；未通过的版本不能视为已兼容 |

## 宿主 API 依据

- [Mozilla IOUtils 定义](https://searchfox.org/mozilla-central/source/dom/chrome-webidl/IOUtils.webidl)：临时文件、备份与 IOUtils 自身的关闭屏障。最后一次保存需在 IOUtils 停止接受新任务之前执行。
- [Zotero HTTP 源码](https://github.com/zotero/zotero/blob/main/chrome/content/zotero/xpcom/http.js)：`cancellerReceiver` 用于取消在途请求；错误对象中的 XHR 字段为 `xmlhttp`。

自动测试模拟这些宿主边界；实际窗口布局、阅读器事件和关闭屏障仍需上述手动验收确认。

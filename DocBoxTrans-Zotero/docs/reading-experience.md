# 第三阶段：阅读体验更新

## 使用方式

- 大模型翻译默认逐步显示结果。翻译中的主按钮变为“取消”，侧栏和弹窗均可停止当前阅读器的请求。
- 取消或流式响应中断时保留已显示的部分译文，并显示中断状态。部分结果不会写入历史，也不会清空拼合区。
- 点击“强制重译”跳过已有译文。拼合区有片段时使用当前片段顺序；否则使用当前任务或选区。此操作会发出新请求。
- PDF 自动清理行内断行、软连字符和疑似行末断词，保留段落、列表、句末和表格边界。该规则是启发式的，遇到排版特殊的文献可关闭“清理 PDF 断行和断词”。EPUB 和 HTML 不执行此清理。
- 拼合区使用 `↑` / `↓` 调整片段顺序，`×` 删除片段。每个片段的完整文本在悬停提示中显示。
- 拼接时移除完整重复和包含的长片段，合并足够长的首尾重叠；短词重复不自动删除。保留片段内部段落，排序后按新首段的位置跳回原文。

## 流式兼容性

实现使用 Zotero 现有 HTTP 请求的 `requestObserver` 读取 XHR `progress`，沿用现有代理与取消机制。参考 [Zotero HTTP 源码](https://github.com/zotero/zotero/blob/main/chrome/content/zotero/xpcom/http.js)。

支持 Chat Completions 的 SSE `delta.content`，不展示 `reasoning_content`。只有收到完成标记或正常结束原因后才将非空译文提交历史；长度截断、格式错误及中断按失败处理。

如果服务忽略 `stream` 而返回普通 JSON，则使用同一次响应的完整译文。不自动重放失败请求。接口不支持流式时，在设置中关闭“逐步显示大模型译文”。有些服务或代理会缓冲输出，此时结果仍可能一次性出现。

目前只有通用大模型引擎增加实时显示；有道等其它引擎仍在完成后显示结果，但同样可以取消。

## 实现与验证

- 任务管线接收 `onProgress` 累计快照，将界面通知限制为约每 80ms 一次；成功、失败和取消仍即时通知。
- 流式通知只更新译文和状态，不重建历史列表、标签输入器或操作按钮。
- 取消、切换选区、请求完成和插件关闭后，过期回调不能继续修改结果或历史。
- 所有成功后的拼合区清理仍按请求时的片段 ID 快照执行，翻译期间新加入的片段保留。
- 离线测试覆盖任意 SSE 分块、CRLF、Unicode、异常流、取消后迟到事件、JSON 兼容响应、强制重译、PDF 清理、重叠拼接和两处界面操作。

执行 `npm test` 和 `npm run build`。当前仍为本地开发构建，包版本保持 `0.3.7`，尚未发布。

## Zotero 内手动验收（尚待执行）

1. 使用支持流式输出的接口，确认侧栏和弹窗逐步显示译文，完成后历史只有一条记录。
2. 在输出中途取消，确认请求停止、部分译文保留，且没有新增历史、拼接片段没有丢失。
3. 切换阅读器并开始新翻译，确认各自的进度和取消按钮只作用于本阅读器。
4. 保持“译文复用”开启，先正常命中旧译文，再点击“强制重译”，确认新请求成功后保留原标签。
5. 在拼合区中上下移动片段，确认两处界面的顺序同步，强制重译使用新顺序。
6. 选取包含跨行断词、双栏文本、公式和表格的 PDF；比较开关文本清理前后的原文输入与译文。
7. 关闭流式设置，确认原有完整响应流程和“测试连接”正常工作。
